同一个客服 Agent 项目，另一个团队也做了一个，技术栈一模一样。区别是他们团队有个做了四年后端的人，上线前做了三件事。结果：**他们的 Agent 上线第一天没出事，我的出了事。**

我越来越确信，做 Agent 的人，分两种。

## 对方做了哪三件事

第一，给每个用户加**请求频率限制**：同一个用户一分钟最多触发 5 次调用，超过的走排队。第二，所有输入先过一个**正则过滤器**，把 HTML 标签、特殊字符、超长文本先清洗掉，再喂检索。第三，做**灰度发布**：新 Agent 先只放 10% 的流量，跑两天没问题再全量。

这三件事，没有一件是 AI 技术。频率限制是 API 网关的标配功能，正则过滤是后端基本功，灰度发布是运维十年前就在做的事。

但就是这三件事，他们的 Agent 上线第一天没出事，我的出了事。

## 两种工程师

**Demo 工程师**：技术博客写得漂亮，GitHub 上 star 很多，录的视频效果很好看。但你把他的 Agent 扔到真实流量里，用户随便折腾两下就崩了。

**上线工程师**：边界条件测过了，异常输入兜底了，限流降级配好了，半夜出问题十五分钟内能止血。这种人做出来的东西，叫"服务"，不叫"Demo"。

从 Demo 到服务，差的不是一个新框架，是**十次被真实用户教育过的经验**。

## 模型 = 发动机，框架 = 底盘，工程 = 刹车和方向盘

这是全文我最想让你记住的一句话。

发动机再猛，没有刹车，上了路就是事故。很多转行做 Agent 的人，车技还没练好就上了高速——不是技术不够，是**工程意识还没跟上**。

模型和框架解决的是"能不能回答"的问题；工程能力解决的，是"能不能扛住真实用户"的问题。能回答和能扛住，中间隔着一万次你没想到的输入。

## 敬畏"线上"两个字

做过四五年后端的人，有个很多刚入行的人不具备的东西——**对"线上"两个字有敬畏心**。

你知道一个接口没做超时处理，高并发下会拖垮整个服务；你知道一个没有限流的 API，早晚会被刷爆；你知道上线不做灰度，就是在拿用户当测试员；你知道日志不打全，出了问题就是两眼一抹黑。这些教训，是拿半夜的睡眠和甲方的怒火换来的。

我前同事做了六年后端，去年转了 Agent 方向。他跟我说了句话我记到现在：现在面试招 Agent 开发，**会搭检索管线的人遍地都是，但上线跑过半年没翻过车的，整个团队可能就一个**。这种人，面试见到就别放走。

## 小结

- 同样的 AI 技术，有没有工程兜底，上线结果天差地别。
- Demo 工程师 vs 上线工程师，差的是"被真实用户教育过的经验"和"对线上的敬畏"。
- 模型和框架解决"能不能回答"，工程能力解决"能不能扛住"。发动机、底盘、刹车方向盘，缺一不可。
- 落到你身上：不必会写限流代码，但要养成"先想边界、留好兜底、重要的事人工复核"的习惯——这已经是上线工程师的思维了。
